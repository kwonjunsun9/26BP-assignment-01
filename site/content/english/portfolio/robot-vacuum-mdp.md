## 프로젝트 소개

**Robot Vacuum MDP**는 로봇청소기가 먼지를 수집하고 충전소로 복귀하는 과정을 Markov Decision Process(MDP)로 모델링한 시뮬레이션 프로젝트입니다.

벽과 고정된 고양이 장애물, 젖은 바닥, 배터리 잔량을 고려해 행동을 선택하도록 구성했습니다. 이동이 항상 의도대로 이루어지지 않는 불확실성도 전이 확률로 표현하고, **Value Iteration과 Policy Iteration으로 기대 보상을 고려한 정책**을 계산했습니다.

## 직접 구현한 범위

공통 패키지의 시뮬레이터, CLI·웹 GUI와 검증 도구를 활용하고, `tasks/` 영역의 MDP 구성 요소와 정책 계산 로직을 구현했습니다.

- 상태 공간 생성과 종료 조건 정의

## 환경을 MDP로 표현하기

### 상태 공간과 종료 조건

로봇의 상태를 `(x, y, dirt_mask, battery)`로 정의했습니다. 위치와 배터리 잔량에 더해 여러 먼지의 상태를 비트마스크 하나로 표현했습니다. 벽 좌표는 상태 공간에서 제외하고, 복귀·충전 지점은 포함했습니다.

먼지를 모두 제거하고 충전소에 도착하면 임무를 완료합니다. 배터리 고갈은 실패에 해당하는 종료 조건으로 구분했습니다. 종료 상태는 반복 가치 계산에서 건너뛰어 불필요한 계산을 줄였습니다.

### 확률적 전이 모델

이동, 청소, 충전의 가능한 결과를 구분하고, 이동 후 재오염 가능성까지 결합해 다음 상태의 확률을 계산했습니다. 각 결과에는 다음 상태와 보상, 배터리 변화와 이벤트 정보를 연결했습니다.

보고서의 전이 검사 예시에서는 의도한 이동 방향의 확률이 **0.95**, 두 측면으로 미끄러질 확률이 각각 **0.025**로 출력되어 확률 합이 1임을 확인했습니다. 이 수치는 해당 검사 사례의 기록입니다.

## 보상을 바꿔 행동을 개선한 과정

초기에는 먼지 수집 보상에 비해 이동 비용이 작아, 불필요하게 먼 거리를 돌아가거나 청소 후 복귀 전에 배터리가 고갈되는 사례가 있었습니다.

목표를 먼지 수집에만 두지 않고 **청소를 마친 뒤 효율적으로 복귀하는 미션**으로 재정리해 보상을 조정했습니다.

| 항목 | 초기 설정 | 조정한 설정 |
| --- | --- | --- |
| 청소 성공 | +5 | +2 |
| 청소 완료 후 충전소 복귀 | +50 | +100 |
| 기본 이동 비용 | -0.01 | -0.1 |

배터리 고갈에는 -100, 빈 바닥 청소·벽 충돌·불필요한 충전 등의 상황에는 별도 페널티를 부여했습니다. 고양이 충돌과 젖은 바닥 통과도 비용으로 반영했습니다.

보상 조정 후 복귀 행동이 달라지는 양상을 관찰했습니다. 다만 장애물과 페널티 배치에 따라 먼지 수집을 포기하고 충전소 주변을 순회하는 사례도 남아, 보상 설계와 임무 성공 여부를 함께 검증할 필요가 있었습니다.

## 두 가지 정책 계산 방식

**Value Iteration**에서는 각 상태에서 가능한 행동의 Q-Value를 계산하고, 가장 큰 값으로 상태 가치를 갱신했습니다. 가치 변화량이 허용 오차보다 작아지면 반복을 종료하고, 수렴한 가치 함수를 바탕으로 정책을 추출했습니다.

**Policy Iteration**에서는 현재 정책의 가치를 평가한 뒤, 더 높은 Q-Value를 갖는 행동으로 정책을 개선했습니다. 정책 개선 과정에서 선택된 행동이 더 이상 바뀌지 않으면 반복을 종료하도록 구현했습니다.

두 방식 모두 전이 모델과 보상을 사용하는 Q-Value 계산을 재사용했습니다. 각 다음 상태에 대해 `전이 확률 × (보상 + 할인율 × 다음 상태 가치)`를 합산하는 구조입니다.

## 계산 효율을 개선한 부분

### 상태 조회를 딕셔너리 인덱싱으로 변경

초기 Q-Value 계산에서는 다음 상태의 인덱스를 찾기 위해 상태 리스트를 순회했습니다. 이를 `state_to_idx` 딕셔너리 조회로 바꿔 반복적인 전체 상태 검색을 줄였습니다.

### 계산한 가치를 즉시 반영

Value Iteration에 in-place 방식의 갱신을 적용했습니다. 별도의 새 가치 배열을 만드는 대신 계산한 값을 바로 반영하고, 배터리 잔량이 낮은 상태부터 방문하도록 상태 생성 순서도 조정했습니다.

### 정책이 안정되면 반복 종료

고정된 최대 반복 횟수만큼 수행하던 Policy Iteration에 정책 안정 여부를 판단하는 조건을 추가했습니다. 기존 행동과 개선한 행동을 비교해 변경이 없으면 종료함으로써, 정책이 안정된 뒤에도 반복하던 계산을 줄였습니다.

## 실패 사례와 남은 과제

**충전소 근처를 계속 순회한 사례**  
먼지가 멀리 있고 주변에 젖은 바닥과 벽이 있는 상황에서는, 먼지 수집의 이득보다 이동과 장애물 비용이 커져 임무를 끝내지 못하는 행동이 나타났습니다. 반복 검증의 한 실패 시행에서는 1,000스텝과 보상 -88이 기록되었습니다.

**시작 직후 종료된 사례**  
다른 실패 시행은 0스텝에서 바로 종료되었습니다. 보고서에서는 초기 설정 문제로 추정했으며, 원인을 확정하기 위해 초기 상태와 종료 조건을 추가로 점검할 필요가 있습니다.

이 경험을 통해 정책 계산의 수렴과 실제 미션 성공을 각각 확인해야 한다는 점을 배웠습니다. 후속 과제는 보상 균형 재검토, 반복 행동 감지, 초기 상태·종료 조건 검증 강화입니다.

## 확장 아이디어: 움직이는 고양이

현재 구현에서 고양이는 고정된 장애물입니다. 움직이는 고양이를 반영하려면 상태에 고양이의 위치를 추가하고, 이동 전이와 충돌 비용도 함께 모델링해야 합니다.

이 경우 상태 공간과 계산량이 커지므로, 특징 기반 근사와 강화학습으로 확장하는 방향을 보고서에서 검토했습니다. 이는 후속 확장 아이디어입니다.

## 배운 점과 개발 과정

상태·전이·보상이 Q-Value와 정책 계산으로 연결되는 과정을 직접 구현하며, 보상 수치가 실제 행동을 어떻게 바꾸는지 확인했습니다. 또한 같은 알고리즘도 상태 조회 방식과 종료 조건에 따라 불필요한 계산량이 달라질 수 있음을 경험했습니다.

ChatGPT를 문법 오류 수정과 코드 리뷰에 활용하고, 보상 체계 조정, Q-Value 인덱싱, Policy Iteration 종료 조건 개선에 도움을 받았습니다. 변경 내용은 CLI·웹 GUI 실행과 제공 검증 스크립트의 결과로 확인했습니다.

## 실행 방법

제공 패키지에서 의존성을 준비하고 CLI 또는 웹 GUI로 실행합니다.

```bash
uv sync
python main_cli.py
python main_web.py
```

웹 GUI 주소는 `http://127.0.0.1:5050`입니다. 아래 도구로 정책 비교와 반복 성능 검증을 수행합니다.

```bash
python tools/test_planners.py
python tools/verify_performance.py
```
